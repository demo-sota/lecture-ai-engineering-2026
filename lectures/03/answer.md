## 宿題

- 取り組んだレベル：基礎
- やったこと：app/tools.py の search_glossary の docstring を1か所だけ変え、演習と同じ質問「LoRA とQLoRAの違いは？」を `--trace` 付きで実行して比べた。あわせて、モデルを通さずに search_glossary を直接呼び、各検索語で返る用語を確かめた。

```diff
-    答える前に使うこと。query には調べたい用語を1つだけ入れる（例: "LoRA"）。
+    答える前に使うこと。query には調べたい用語をまとめて入れる（例: "LoRA"）。
```

- 結果：

| | 変更前（1つだけ） | 変更後（まとめて） |
|---|---|---|
| tool call | `'LoRA'`、`'QLoRA'` の2回 | `'LoRA QLoRA'` の1回 |
| requests | 2 | 2 |
| tool_calls | 2 | 1 |
| input_tokens | 1196 | 885 |
| output_tokens | 175 | 203 |
| cost | 0.0007963 | 0.0007730 |
| 回答の内容 | LoRA と QLoRA の違いを説明、関係する回：第2回 | 同じ内容、関係する回：第2回 |

search_glossary を直接呼んだ結果：

| query | 返った用語 |
|---|---|
| `LoRA` | LoRA、ランク（LoRAのr）、QLoRA |
| `QLoRA` | QLoRA、LoRA |
| `LoRA QLoRA` | LoRA、QLoRA |

- 気づき・疑問：
  - 気づき
    1. docstring の「1つだけ」を「まとめて」に変えただけで、search_glossary の呼び出しが2回から1回になり、引数も `'LoRA QLoRA'` に変わった。モデルは docstring の文に従って、ツールの呼び方を決めていると考えられる。
    2. tool_calls は 2→1 に減ったが、requests は 2 のままだった。変更前も、2つの検索は1回の応答でまとめて依頼されていた（`[tool call]` が2つ続いてから `[tool return]` が返っている）。そのため、検索をまとめても LLM の呼び出し回数は減らなかった。
    3. input_tokens は 1196→885（約26%減）になった。直接呼んだ結果では、変更前の2回の検索で計5件（LoRA と QLoRA がそれぞれ2回ずつ）が返り、変更後は2件だった。入力トークンが減ったのは、重複した検索結果がなくなったためと考えられる。
    4. `'LoRA QLoRA'` でも2件ともヒットした。search_glossary は、空白を除いて小文字にした検索語（"loraqlora"）に3文字以上の用語名が含まれていれば一致とみなす（`len(n) >= 3 and n in q`）。まとめた検索がうまくいったのは、この部分一致の実装のおかげだった。
    5. 変更後は「ランク（LoRAのr）」が返らなくなった。検索結果は MAX_RESULTS=3 件で切られる仕様でもある。
    6. 回答の内容と「関係する回：第2回」は、変更の前後で変わらなかった。
  - 疑問
    1. output_tokens は 175→203 に増えたが、各条件を1回ずつしか実行していないため、変更の影響なのか実行ごとのばらつきなのかは区別できない。
    2. まとめる用語が3つ以上の質問（例：LoRA・QLoRA・PEFT）では、MAX_RESULTS=3 によって一部の用語が結果から漏れるかどうかは確かめていない。
